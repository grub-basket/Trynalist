# 0.28.1

## Hotkeys follow the keyboard, not the active pane

Trynalist's default shortcuts could fire while you were typing somewhere else
entirely — most visibly, `Mod+A` in another plugin's sidebar input ran
Trynalist's "select one more level upward" instead of selecting that input's
text.

The cause: the check asked whether a Trynalist document was the *active pane*,
which is not the same question as where the keyboard is. A sidebar takes focus
without changing the active pane, so with a document open in the main pane the
check said yes while you were typing elsewhere. Every shipped default —
`Mod+A`, `Mod+F`, `Mod+[`, `Mod+]`, `Mod+.` and the rest — was affected.

Commands now require focus to actually be inside the document. The same hole
existed in the `Mod+Enter` handler, which had no focus check at all and would
have toggled a checkbox out of view; it now hands the chord back to whoever
should receive it.

Nothing changes when you are working in a Trynalist document: every shortcut
behaves exactly as before.
