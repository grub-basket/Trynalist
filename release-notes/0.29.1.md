# 0.29.1

## `Alt+Enter` works

A line break inside an item did nothing for three releases. The cause was not
the shortcut: the key press arrives, the command fires, and the handler runs
every time. Two other things were hiding the result, and both only bite when the
break goes at the **end** of a line — which is exactly where you put it when
you want a new line.

1. Saving a row trimmed trailing whitespace, which removed the break. A save
   fired a few milliseconds after the insert and wrote the trimmed text back
   over it.
2. A line break at the very end of an editable line renders no visible empty
   line, so even before the save undid it there was nothing to see.

Both are fixed, and `Alt+Enter` now also creates an undo entry — it never did,
because the row is rewritten directly rather than typed into.

Every internal test of this feature had put the break in the *middle* of a line,
where neither problem occurs. That is why it kept passing.

The known-issue note about `Alt+Enter` has been removed from the README.
`Shift+Enter` (into an item's note) and `Mod+Shift+Enter` continue to work as
before.
