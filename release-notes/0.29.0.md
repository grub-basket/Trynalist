# 0.29.0

A rendering pass, from an audit of every construct across all four views.

## Article view renders notes

Article view was not rendering notes at all — it ran them through the inline
renderer, so a fenced code block collapsed onto a single line with its backticks
showing. Notes there now get the same treatment as in the outline and flat
views: syntax highlighting, tables, callouts, maths, embeds.

## Inline syntax that was showing as raw text

Item text is rendered by Trynalist rather than by Obsidian, and several things
were missing from that renderer. All of these now work, in every view:

- `*italic*` and `***bold italic***`. Dynalist used `__italic__`, which is still
  supported — but this is Obsidian, and `*` is what people type.
- `==highlight==`
- Inline `$maths$`, alongside the block form
- `~subscript~` and `^superscript^`

**Backslash escapes now work.** `\*not italic\*` shows the asterisks and stays
unformatted; previously the backslashes appeared literally *and* the formatting
fired anyway.

## Blocks inside notes no longer stretch the whole pane

Obsidian styles these for a full-width page. Dropped into an outline on a wide
window, a note's horizontal rule and callouts ran the entire width of the pane
while the text beside them was a few hundred pixels. They are constrained to a
readable column now.

Also fixed in the same pass:

- **Blockquotes** had lost their bar, their indent and their spacing entirely.
- **Tables** had no borders or cell padding.
- **Code blocks** had no background, so the language/copy strip read as a
  floating label rather than the top of the block.
- **Display maths** centred itself across the whole pane, far from its own note.

## Mind map

Node labels showed raw markup (`**bold**`, `==highlight==`). They are reduced to
plain words, which is what a small box wants.

## Known issue

`Alt+Enter` (line break inside an item) does not work on macOS. The command is
registered and the action itself is correct, but the key press appears never to
reach the plugin — most likely because macOS treats Option as a text-input
modifier. Use the note instead: `Shift+Enter` moves into an item's note, `Enter`
there makes ordinary new lines, and `Shift+Enter` brings you back.
`Mod+Shift+Enter` is bound to the same action and does work.
