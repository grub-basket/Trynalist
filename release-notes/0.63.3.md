# 0.63.3

Since 0.60.0: a three-state check cycle, notes you can arrow out of, an undoable
paste, an image viewer, a leaner item menu, and — this release — coloured depth
badges in the flat views. Plus a run of correctness fixes, including one that
was taking Select-All away from other plugins.

## 0.63.3 — flat-view depth badges

Flattening an outline throws away indentation, and the `L3`-style badge that
replaced it looked identical at every level, so a run of rows read as one
undifferentiated list. Each badge now carries a colour per level.

The colour comes from rotating the hue 47° per level, not from a light-to-dark
ramp: lightness is fixed per theme, so contrast stays identical at every depth
(measured worst case 5.76:1 across light and dark) where a shade ramp would have
left the shallow end unreadable and the deep end indistinct. Adjacent levels
land far apart on the colour wheel; the cycle only repeats at level nine.

Flat **search** results carry the same badge, for the same reason — which meant
laying each result out in two columns so the badge sits beside the whole result
rather than on a line of its own.

## 0.63.2 — Select-All no longer leaks out of Trynalist

An Obsidian command hotkey is global: it fires wherever the keyboard focus
happens to be. Binding Mod+A to "select one more level upward" therefore took
Select-All away from every text field in every other plugin (found in Stashpad's
composer). The command's default binding is dropped; the ladder still works
inside a Trynalist view, because the view already claims Mod+A while it holds the
keyboard, and no longer reaches beyond it. Mod+Shift+A is unaffected — it is also
global, but not a chord text fields use.

## 0.63.1 — customiser icons were invisible

The icons in the menu customiser rendered and were correctly coloured, and were
zero pixels wide. An `<svg>` in a flex container is a flex item that may shrink,
so its `width` was a suggestion the layout squeezed to nothing; both the icon and
its button are now fixed-size. Two entries that showed their internal id
(`folding`, `customise`) are labelled, and unknown ids now derive a readable
label instead of leaking the id.

## Tooling — layout invariants

A script (`scripts/layout-invariants.js`) asserts six relationships that no
single element is guilty of breaking: icons are square and non-zero, an icon fits
its control, controls in a row share a centre line, mobile touch targets are big
enough, a clickable overlay is actually reachable, and nothing has collapsed in
exactly one axis. Every one of these was a real bug this cycle that an
"does it exist" check could not see. The checker was validated by re-injecting
each original bug and confirming it fires.

## 0.63.0 — image viewer and a shorter item menu

Clicking an inline image opens it full size with a rail of every image in the
document. Arrow keys walk the rail and wrap, clicking a thumbnail jumps to it,
and the current thumbnail scrolls itself into view. The clicked image is added
to the rail even when the document scan missed it, so an oddly-linked embed still
opens.

The item menu dropped from 32 entries to 25 by grouping three sets into
submenus — **Folding** (collapse all, expand all, collapse siblings, expand to
level), **Copy a link** (deep link, deep link zoomed, copy as mirror), and
**Copy** (copy, cut, copy with timestamps, duplicate). Nothing was removed;
"Collapse" itself stays top-level.

## 0.62.0 — notes are not sealed boxes

- **Arrows at a note's edges.** Up from a note's first line moves to the item the
  note belongs to; Down from its last line moves to the next item, creating one
  if there is nothing below. Interior lines are left to the browser. Dynalist
  parity — previously the only way out of a note was the mouse or Escape.
- **Paste is undoable.** A single-line paste went in without a snapshot, so undo
  skipped past it and reverted the previous structural change instead (cut
  something, paste elsewhere, undo, and the cut was discarded while the paste
  stayed). It now snapshots before inserting.
- **Scroll survives a render.** Rebuilding the view snapped the scroller to the
  top, so an undo deep in a long note restored the state correctly but threw you
  to the top of the document. Scroll position is captured before the rebuild and
  restored after, unless a focused row has scrolled itself into view.

## 0.61.1 — three-state check cycle

Mod+Enter cycles no checkbox → completed → unchecked → no checkbox. The first
press still checks the item off, so the common case is unchanged; the new rung is
an item that has a checkbox and is not ticked, which previously required adding a
checkbox from the menu. A recurring item still rolls forward on the first step.

## 0.61.0 — Dynalist wording and smaller fixes

- **Sort menus use Dynalist's wording verbatim** ("Title (A to Z)", "Date (new to
  old)", "Reverse current"), so someone arriving from Dynalist recognises the
  option they already know.
- **Quotes and backticks no longer double.** Growing a symmetric pair is right for
  marks that mean something doubled (`**` bold, `~~` strike, `==` highlight) and
  wrong for quotes: typing `"` twice now leaves `""` with the caret between them,
  not `""""`. Asterisk, tilde and equals still grow.
- **Mod+O works with nothing focused.** Its guard refused the chord when focus
  fell to the page body; view-level chords (Mod+O, Mod+F, Mod+Shift+F) now refuse
  only when focus sits in another plugin's input.
- **"Add note"** takes a note-shaped icon rather than the generic text one.
- **"Customise this menu…"** is now in the menu itself, not only in Settings.
- The **no-references notice** puts the item's name on its own line after a colon,
  so a long item name no longer runs into the sentence.

## Known issue

An intermittent report of the caret jumping to the front of a line on Enter could
not be reproduced across item text and notes; it is logged as an open mystery
with the facts that would settle it.
