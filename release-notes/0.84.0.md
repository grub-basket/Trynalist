# 0.84.0

Everything since 0.83.0: `{{date}}` and `{{time}}` in file names follow your Templates formats. Requires Obsidian 1.11.4 or later.

## Highlights

- **Dates match your Templates settings.** In the file name template, `{{date}}` and `{{time}}` now use the Date format and Time format from Obsidian's core Templates plugin, the same way Obsidian's own templates do. With nothing set there, Templates' defaults apply (`2026-10-29` and `02-20`).
- **New toggle.** "Use the template plugin's date and time formats" (on by default). Turn it off for the fixed `YYYY-MM-DD` and `HHmmss`.
- **Written formats still win.** `{{date:YY-MM-DD}}` is always used as written.
- **Behaviour change:** a template with a plain `{{time}}` now gives `02-20` (Templates' `HH:mm`, with the colon made file-safe) instead of `022022`, unless the toggle is turned off.

## All changes

### 0.84.0

- New setting **Use the template plugin's date and time formats**, between Text pattern and Example.
  - On, with Templates enabled: a plain `{{date}}` / `{{time}}` (and `{{date:}}` / `{{time:}}`) uses Templates' Date format and Time format. When those are unset, Templates' own defaults `YYYY-MM-DD` and `HH:mm` apply.
  - Off, or Templates disabled: `YYYY-MM-DD` and `HHmmss`, as in 0.83.0.
- Characters a file name can't contain, such as `:` and `/` from a format, become `-`.
- The formats are read from Obsidian's settings folder (`core-plugins.json` and `templates.json`), so turning Templates on or off is respected.
- Changing the Templates formats while Obsidian is open affects new items within about 15 seconds; the files are read again only when a new file is about to be named.
- Items named while the formats are being read wait for that read, and a read that finishes after a newer one is ignored, so switching the toggle takes effect immediately.
- The Example row in settings uses the current formats.
- Developer comment fixes (no change in behaviour).
