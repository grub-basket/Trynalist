# 0.86.2

Everything since 0.86.1: file and folder names that work on Windows, and paths that stay within Windows' length limit. Requires Obsidian 1.11.4 or later. Existing files and folders keep their names; only names created from now on change.

## Highlights

- **Shorter paths for deep outlines.** Windows limits a whole path to 260 characters, and File Explorer, OneDrive, git and zip tools still enforce it. A deep Dynalist import could pass that. New item files now stay within 200 characters inside the vault: in a deep folder, the item's file name is shortened and keeps its id.
- **Shorter folder names, full titles.** Document folders are named with the first 60 characters of the title. The title itself is kept in full and is what the panel and tabs show.
- **No more hidden characters in file names.** Text pasted with invisible control characters, for example from a terminal, no longer ends up in an item's file name, where Windows couldn't create or sync it.
- **Windows line endings.** Items, reminders and Stashpad notes saved by a Windows editor are read correctly.
- **Two more reserved names.** `COM¹`–`COM³` and `LPT¹`–`LPT³`, which Windows reserves, get " (name)" added like `CON` and `NUL` already do.

## All changes

### Tooling

- This repository now builds with pnpm: `pnpm-lock.yaml` and `pnpm-workspace.yaml` replace `package-lock.json`, and the release workflow runs `pnpm install --frozen-lockfile && pnpm run build`. To build from source, run `pnpm install` and then `pnpm run build`.
- The development build checks that the version number isn't already used by another branch, a tag or a reservation. That check is development tooling only and isn't part of this repository's build.

### 0.86.2

- Item file names (the default `{{slug}}-{{id}}`) drop control characters (U+0000–U+001F). Other template parts already did.
- `COM¹`, `COM²`, `COM³`, `LPT¹`, `LPT²` and `LPT³` are treated as reserved Windows device names, so a document, folder or attachment with one of those names gets " (name)" appended.
- Four readers that split front matter by hand now handle Windows (CRLF) line endings and a byte-order mark: the check for whether an existing file belongs to an item, the `{{parent}}` file-name template part, the text a reminder shows, and the Stashpad converter.
- New item files keep their vault-relative path within 200 characters. In a deep folder the name is shortened, a trailing item id is kept, and the words before it are cut. Names are never shorter than 20 characters. Shallow folders get exactly the names they did before.
- Document folders and their `.trynalist` files, new plain folders, trash groups and pasted attachments are named with at most 60 characters. Document titles keep up to 120 characters.
- A document renamed to a long title that shares its first 60 characters with another document's gets a numbered folder (`… 2`) instead of an "already exists" error.
- Dynalist folder names keep the 120-character limit, so Update from Dynalist and resuming an import find the folders earlier versions created. (An earlier version of this change capped them at 60.)
- When the plugin looks for an item file already on disk, it checks both the shortened name and the full name, so a file an earlier version wrote in a deep folder is reused rather than duplicated.
- The shared front-matter parser handles CRLF line endings and a byte-order mark itself. This also covers restoring from the Trynalist trash, the Stashpad converter's fallback, and loading recently written files.
- Renaming a document to the exact title of another document in the same folder is refused with "already exists". Every sibling document is checked, including ones from earlier versions whose folders carry the full title. (An earlier version of this check only looked at the folders it passed while numbering.)
