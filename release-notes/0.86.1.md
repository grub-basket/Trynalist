# 0.86.1

Everything since 0.85.0: more fixes for the mobile keyboard toolbar, plus Undo and Redo. Requires Obsidian 1.11.4 or later. Desktop is unchanged. 0.86.0 was not published on its own, so its changes are listed here too.

## Highlights

- **Toolbar clears the bottom bar.** With the keyboard hidden, the keyboard toolbar now sits just above Obsidian's bottom navigation bar instead of on top of it. On iPad, which has no bottom bar, it stays at the screen edge.
- **Toolbar rides the keyboard on iOS.** With the keyboard up, the toolbar sits directly on the keys again. A build before this one lifted it by the height of the bottom bar.
- **Undo and Redo buttons.** Two new toolbar buttons undo and redo both typing and structural changes such as indenting or moving items. A toolbar that has already been customised keeps its layout; add the buttons from the gear.
- **Customise the toolbar from settings.** The toolbar customiser can now also be opened from the plugin's settings, next to "Customise the item menu".
- **Icons in the item menu customiser.** Each entry shows its icon to the left of its name.
- **The last rows scroll clear while typing.** The outline keeps enough space at the bottom for its last rows to scroll above the toolbar.

## All changes

### 0.86.0

- With the keyboard down, the toolbar's bottom is set to how far `.mobile-navbar` reaches up from the screen bottom. The measurement uses the bar's resting position, so its auto-hide slide does not move the toolbar. It is re-measured on viewport resizes, 350 ms after them, when Obsidian changes its navigation-mode body classes, and when the bar finishes a transition. All listeners are released when the toolbar unmounts.
- With no bottom bar (iPad), the measurement is 0 and the toolbar stays at the screen edge with the home-indicator inset.
- While above the bottom bar, the toolbar drops its home-indicator padding, because the bottom bar already covers the home indicator.
- The outline's bottom padding adds Obsidian's `--view-bottom-spacing`, so the last rows can scroll clear of both bars.
- New "Undo" (`undo-2`) and "Redo" (`redo-2`) toolbar actions, placed after "Dismiss keyboard". They call the document's own undo and redo, which include typing. They also appear in the Mod+K command bar.
- New "Customise the mobile toolbar" setting, opening the same dialog as the toolbar's gear. Saving rebuilds the toolbar of every open document.
- The item menu customiser shows each entry's icon. Icons are read from each menu entry's own builder, so the customiser always matches the menu. Entries without an icon keep a blank slot, and hidden entries dim the icon with the name.
- The outline's bottom padding never drops below 96 px. Obsidian's floating bottom bar makes `--view-bottom-spacing` strongly negative while the keyboard is up, which had clamped the padding to 0.

### 0.86.1

- The toolbar no longer floats above the keyboard on iOS. iOS resizes the webview for the keyboard, so neither the viewport gap nor `--keyboard-height` reported one, and the toolbar was lifted by the bottom bar's height. The keyboard now also counts as up on Obsidian's `keyboardWillShow` and `keyboardWillHide` events, on Obsidian's internal soft-keyboard flag, and when the visual viewport is more than 120 px shorter than its tallest height at the current width. Rotation resets that height.
- Those indirect signals count only while a text field has focus. A missed hide event, or an Android split-screen window, can no longer drop the toolbar onto the bottom bar. The direct measurements still count on their own.
