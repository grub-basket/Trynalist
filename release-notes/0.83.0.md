# 0.83.0

Everything since 0.82.0: choose how new item files are named. Requires Obsidian 1.11.4 or later.

## Highlights

- **File name template.** Settings → File name template sets how each new item's file is named. The default, `{{slug}}-{{id}}`, gives the same names as before, so nothing changes unless you edit it.
- **No random id needed.** Leave out `{{id}}` if your item text is already unique. When a name is taken, ` 2`, ` 3` and so on are added (`Topic.md`, `Topic 2.md`).
- **Text pattern.** An optional regular expression pulls parts out of the item's text into `$1`–`$9`. For example, `(\w+) (\w+)` with `$1 - {{date:YY-MM-DD}} - $2` names "topic keyword" `topic - 26-10-12 - keyword.md`.
- **Live example.** A row under the settings shows the name you'd get as you type.
- **Existing files keep their names.** A template change only affects items created afterwards. Nothing renames existing item files.

## All changes

### 0.83.0

- New settings **File name template**, **Text pattern** and **Example**, under Root folder. Both fields save when you leave them or press Enter. An invalid pattern is refused with a notice, and a reset button restores the default template.
- Template variables:
  - `{{slug}}`: the first words, lowercase, joined by hyphens (the old naming).
  - `{{text}}`: the item's text, with case and spaces kept.
  - `{{id}}`: the item's id.
  - `{{date}}` / `{{date:FORMAT}}` and `{{time}}` / `{{time:FORMAT}}`: Moment formats, based on when the item was created.
  - `{{uuid}}`: a random UUID.
  - `{{parent}}`: the parent item's text.
  - `{{doc}}`: the document name.
  - `$1`–`$9` and `$&` from the text pattern; `$$` gives a literal `$`.
  - An unknown `{{name}}` is left as typed, so the example shows the mistake.
- The template is filled in one pass, so item text that happens to contain `{{id}}` or `$1` is never expanded.
- Cleaning:
  - Dates, link targets and characters that the vault, the filesystem or Markdown links reject are removed from variable values.
  - Separators left behind by empty variables are trimmed.
  - Leading dots and Windows device names are handled as for document names.
  - Names are capped at 200 bytes, so long Chinese, Japanese or Korean text stays within filesystem limits.
- Blank items still start as `item-<id>` and get their real name on their first save.
- Name collisions are resolved in every place items are created: typing, Capture to inbox, restoring a deleted item, imports, duplicates and copies.
  - The check ignores letter case, because macOS, Windows and iOS treat `Topic.md` and `topic.md` as the same file.
  - It also covers files that are still being written, because imports write many files at once.
- A file that already exists under the chosen name is reused only if it belongs to the same item (by id). One item can no longer take over another item's file.
- Two saves of the same new item at the same moment no longer leave a duplicate file.
- Developer notes updated (not shipped).
