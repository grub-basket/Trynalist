# 0.28.0

Mirrors, finished off. Three gaps closed, one of them a quiet data problem.

## Mirrors appear in exports

A mirror used to export as the blank line it literally is, silently dropping
content the document visibly contained. Exports now write a provenance marker —
`*(mirror of "X" in Some Doc)*` — followed by the resolved subtree, so an
export says where content came from rather than presenting a copy as though it
had been written there. A mirror whose source is unavailable exports as an
explicit note rather than a blank.

## Deleting mirrored content asks first

A mirror is the one way a change in one document can blank a row in another,
and the other document has no way to know it happened. Deleting an item now
checks whether anything mirrors it — walking the entire subtree, so mirroring a
grandchild still protects it — names the documents holding those mirrors, and
aborts if you cancel. The mirrors themselves are never deleted; they say their
source is gone and can be removed from their own menus. The delete remains
undoable.

Mirrors held in documents outside the configured root folder are not found by
this check, since those documents are not managed by the plugin.

## A mirror no longer claims a present source is missing

The resolver cached every source document it opened and never let go. A mirror
therefore showed its source as it was when first read, and — worse — once the
source had changed, an item that was still there could resolve as "source is
gone". Sources are now re-read on every repaint.

## Fixes

- `ConfirmModal` now reports a dismissal, so a caller waiting on a yes/no answer
  no longer hangs when the dialog is closed without choosing.
- Mirror change detection compares content rather than object identity, which
  is what keeps the repaint from rescheduling itself indefinitely.
