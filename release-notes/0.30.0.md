# 0.30.0

## The blank-line problem in rendered notes is actually gone

Rendered notes kept showing stray blank lines — between list items, inside
blockquotes, around paragraphs — and every previous fix removed them from one
container only to have them reappear in another. The real cause was one CSS
rule: the note element preserved whitespace for *editing* raw text, and the
rendered markdown inherited that, turning every invisible gap between block
elements into a visible empty line. Preserving whitespace now applies only
while editing. A sweep of every container in the test document finds no
remaining gaps.

## Selecting with Shift+↑/↓ understands multi-line items

Selection now widens in three steps. Inside a multi-line item, `Shift+↑/↓`
grows the text selection a line at a time, exactly as in any editor. Once the
selection reaches the item's edge, the next press selects the whole item as a
block. After that, each press adds the neighbouring item. Previously the first
press jumped straight to the row above with nothing usefully selected.

## Fixes

- **Overdue dates were an unreadable solid red pill** — red text on a red
  background in most themes. The chip is now a translucent tint with legible
  text.
- **Display maths (`$$…$$`) in a note centred itself** across the pane instead
  of starting at the left. It aligns left now; the earlier fix had lost a
  specificity fight with MathJax's own stylesheet.
